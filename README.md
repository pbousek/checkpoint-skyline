# Skyline -- Prometheus + Grafana for Check Point Skyline

Standalone Docker Compose stack for receiving metrics from Check Point Skyline via
**Prometheus Remote Write** (HTTPS + basic auth) and visualizing them in Grafana.

Based on: **https://support.checkpoint.com/results/sk/sk178566**

> Czech version: [README.cs.md](README.cs.md)

## Components

| Component | Description |
|---|---|
| [Prometheus](https://prometheus.io/docs/introduction/overview/) | Receives metrics from Check Point via Remote Write, stores in TSDB |
| [Grafana](https://grafana.com/docs/grafana/latest/) | Metrics visualization, dashboards auto-loaded from `dashboards/` |
| [Caddy](https://caddyserver.com/docs/) | Reverse proxy in front of Grafana, handles HTTPS |

## Architecture

```
Check Point device
  \-- OpenTelemetry Collector
        \-- Prometheus Remote Write (HTTPS + basic auth)
              \-- Prometheus :9090
                    \-- Grafana :3000  <-- Caddy :443
```

## Requirements

- Docker + Docker Compose plugin
- 2 vCPU, 2 GB RAM
- Port `9090` reachable from Check Point network
- Port `443` reachable for administrators (Grafana)

## Quick Start

### 1. Configuration

```bash
cp .env.example .env
```

Edit `.env` -- at minimum:

```
GRAFANA_DOMAIN=promtest.example.com   # server DNS or IP
GRAFANA_ADMIN_PASSWORD=strong-password

CADDY_TLS_MODE=internal               # see TLS section below

PROMETHEUS_SERVER=10.0.0.42           # IP/hostname of this server
PROMETHEUS_AUTH_USER=skyline
PROMETHEUS_AUTH_PASSWORD=strong-password
```

### 2. Prometheus certificate

The script generates a self-signed TLS certificate for Prometheus. Pass the server
hostname or IP as arguments -- they are written into the certificate SAN and verified
by the Check Point collector on each connection.

```bash
./gen-certs.sh <hostname> [<ip>]
# example:
./gen-certs.sh promtest.example.com 10.0.0.42
```

Generates `certs/prometheus.crt` (certificate) and `certs/prometheus.key` (private key).
Upload `prometheus.crt` to the Check Point collector as its CA cert.

### 3. Generate configuration

```bash
./setup.sh
```

Generates:
- `prometheus/web.yml` -- TLS + basic auth (bcrypt-hashed password)
- `caddy/Caddyfile` -- TLS mode based on `CADDY_TLS_MODE`
- `certs/grafana.*` -- self-signed cert for Grafana (only for `CADDY_TLS_MODE=custom`)
- `payload.json` -- Check Point collector configuration

### 4. Start

```bash
docker compose up -d
docker compose logs -f
```

### 5. Check Point collector

Run on the Check Point gateway:

```bash
sklnctl export --set "$(cat payload.json)"
```

`payload.json` contains the endpoint URL, certificate, and credentials -- generated by `setup.sh`.

## Scripts

### gen-certs.sh

Generates a self-signed TLS certificate for the Prometheus Remote Write endpoint.

```
Usage:    ./gen-certs.sh <hostname> [<ip>]
Examples: ./gen-certs.sh promtest.example.com
          ./gen-certs.sh promtest.example.com 10.0.0.42
```

Output:
- `certs/prometheus.crt` -- upload to Check Point collector as CA cert
- `certs/prometheus.key` -- stays on the server, do not share

Hostname and IP are written into the certificate SAN (Subject Alternative Name) --
the Check Point collector verifies them match the endpoint address.

### setup.sh

Reads `.env` and generates all configuration files. Run after every
`git pull` or `.env` change.

Prerequisites:
- `.env` exists (copy from `.env.example`)
- `certs/prometheus.crt` exists (run `gen-certs.sh` first)

What it generates:

| File | Description |
|---|---|
| `prometheus/web.yml` | TLS + basic auth with bcrypt-hashed password |
| `caddy/Caddyfile` | TLS mode based on `CADDY_TLS_MODE` |
| `certs/grafana.crt/key` | Self-signed cert for Grafana (only `CADDY_TLS_MODE=custom`) |
| `payload.json` | Check Point collector config (endpoint + cert + credentials) |

Uses `python3-bcrypt` for bcrypt hash generation; falls back to Docker image `httpd:2`.

## Grafana TLS (Caddy)

Configured via `CADDY_TLS_MODE` in `.env`. `setup.sh` generates the Caddyfile.

| Mode | Description | When to use |
|---|---|---|
| `letsencrypt` | Caddy obtains certificate from Let's Encrypt automatically | Public server with DNS record and ports 80+443 open from internet |
| `internal` | Caddy generates its own local CA | Internal network without public IP; browser will show untrusted cert warning |
| `custom` | `setup.sh` generates self-signed cert into `certs/grafana.*` | Internal network; add cert to OS/browser trust store to avoid warnings |

For `custom` mode: after running `setup.sh`, import `certs/grafana.crt`
into the trust store on your machines/browsers.

## Dashboards

Official Check Point dashboards available in the **Downloads** section:
**https://support.checkpoint.com/results/sk/sk178566**

Place JSON files into `dashboards/`. Grafana loads them automatically and checks
for changes every 30 seconds. Subdirectories appear as folders in Grafana.

## Directory structure

```
skyline/
+-- docker-compose.yml
+-- .env                    # configuration (not in git)
+-- .env.example            # template
+-- gen-certs.sh            # generates certs/prometheus.*
+-- setup.sh                # generates web.yml, Caddyfile, payload.json
+-- payload.json            # Check Point collector config (not in git)
+-- certs/                  # certificates (not in git)
|   +-- prometheus.crt/key
|   \-- grafana.crt/key     # only for CADDY_TLS_MODE=custom
+-- prometheus/
|   +-- prometheus.yml
|   \-- web.yml             # generated by setup.sh
+-- caddy/
|   \-- Caddyfile           # generated by setup.sh
+-- grafana/provisioning/
+-- dashboards/             # JSON dashboards
\-- alertmanager/           # disabled, ready to enable
```
